* Development Workflow

Emacs is the editing, navigation, diagnostics, compilation, and review surface.
Use Foot with tmux or Herdr for builds, tests, logs, Git commands, and agent
CLIs. The workflow is intentionally direct: choose the agent, model,
permissions, and working directory in its CLI instead of using a repository
wrapper.

** Work in Emacs

Project commands use Emacs's built-in =C-x p= prefix:

- =C-x p p=: switch project.
- =C-x p f=: find a project file.
- =C-x p b=: switch project buffer.
- =C-x p g=: search the project.
- =C-x p c=: compile from the project root.
- =C-x p k=: kill project buffers.

Use =F10= for buffers, =Shift-F10= for recent files, =C-.= for contextual
Embark actions, and =C-x g= for Magit. Completion uses Vertico, Consult,
Corfu, Orderless, and Marginalia; project navigation stays on built-in
=project.el= rather than a separate project wrapper.

** Language and build support

Eglot starts the configured language servers for Java, C/C++, Zig, YAML, Nix,
and Rust when their executables are available. Java buffers use =java-ts-mode=
with the Home Manager-managed tree-sitter grammar, JDT LS, and
=google-java-format=. Spring Boot CLI is also workstation-managed. Java
runtimes, Maven, Gradle, and other project-specific Java tools are supplied
through Mise rather than the workstation Nix profile.

Use standard Xref and Eglot commands for navigation and refactoring. Supported
language buffers format through Eglot on save where configured. Run project
builds and tests through =C-x p c= or directly in a terminal so the repository's
native Make, Maven, Gradle, Nix, or other build interface remains visible.

Useful terminal tools include =rg= and =fd= for search, =ast-grep= for
structural search, =jq= and =yq= for structured data, =watchexec= for simple
reruns, =difft= for readable diffs, =lazygit= and =lazydocker= for focused TUI
work, and =mise= for project toolchain selection.

** Review changes

Use =C-c g d= to review tracked changes against =HEAD= with Difftastic. Git
Gutter marks changed lines in file buffers:

- =C-c g p=: visit the previous hunk.
- =C-c g n=: visit the next hunk.
- =C-c g h=: preview the current hunk.

Magit refines changed words within every displayed diff hunk. Before applying
workstation configuration, also inspect the terminal diff so copied files,
generated references, and unrelated local changes are visible.

** Terminal sessions

Niri opens Foot with =Mod-T=. Use =Mod-Shift-T= for Herdr, whose prefix is
=C-a=. Its main controls are:

- =C-a c=: create a tab; =C-a p=/=C-a n=: previous/next tab.
- =C-a 1..9=: select a tab.
- =C-a h/j/k/l=: focus a pane.
- =C-a |= and =C-a -=: split vertically or horizontally.
- =C-a r=: enter resize mode; =C-a z=: zoom the active pane.
- =C-a [=: copy mode; =C-a q=: detach; =C-a Shift-r=: reload config.

tmux remains available for persistent or remote-friendly sessions. Its prefix
is =C-x=:

- =C-x |= and =C-x -=: split in the current pane's directory.
- =C-x h/j/k/l=: select a pane; uppercase =H/J/K/L= resizes it.
- =C-x C-h=/=C-x C-l=: select the previous/next window.
- =C-x C-c=: copy the tmux buffer to Wayland; =C-x C-v=: paste from Wayland.
- =C-x r=: reload =~/.tmux.conf=.

tmux enables focus events, mouse support, a 50,000-line history, automatic
window renumbering, and session restoration through TPM, tmux-resurrect, and
tmux-continuum.

** Share context with agents

Use =C-c x= to copy explicit project context:

- =C-c x f=: copy the current project-relative =file:line=.
- =C-c x r=: copy the active region with its file and line range.

Paste that context into Codex or Claude from a regular terminal, tmux, or Herdr
session. Keep planning and implementation permissions explicit in the agent
CLI; this repository no longer supplies custom agent-loop, session, or
worktree wrappers.

The repository-managed =manage-makefile= skill is linked into both agents'
global skill directories by =make sync-skills= and by the Home Manager
configuration.

** Maintain this configuration

Inspect the command surface and prerequisites before changing the workstation:

#+begin_src sh
  make help
  make doctor
#+end_src

After editing repository-managed configuration or scripts, run the narrowest
relevant check followed by the repository check:

#+begin_src sh
  make check
#+end_src

=make check= validates the Make interface and required files, builds the keyd
package without switching it, validates Niri, checks shell syntax and
ShellCheck-clean host scripts, and checks Emacs parentheses.

Review the final diff before changing the live environment. Apply only when
intended:

#+begin_src sh
  make sync
  make switch
  # or: make apply
#+end_src

=make sync= copies the repo-managed Home Manager, Emacs, tmux, Niri, Foot,
Herdr, Newsboat, helper commands, wallpaper, and shared skill files. =make
switch= applies the repository flake. Neither command deploys keyd or changes
host packages and services; those remain separate explicit operations.
