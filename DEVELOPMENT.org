* Development Workflow

Emacs is the editing, navigation, diagnostics, and review surface. Codex runs in
Ghostty inside a project-scoped tmux session. The browser stays separate for
documentation and application testing.

** Start a project

From niri, press =Mod+P= and select a top-level project from =~/work=. The
launcher starts three apps; Niri window rules place them on the existing
workflow workspaces:

- =build=: GUI Emacs opened through =emacsclient=.
- =ops=: Ghostty attached to the project's tmux session.
- =scratch=: the configured browser using the project-only
  =dev.vals.ProjectBrowser= app ID.

Normal browser windows do not match the project rule, so documentation windows
can remain in =write=.

Start the terminal workflow directly when the full desktop preset is not needed:

#+begin_src sh
  dev-session ~/work/project
  dev-session --launch ~/work/project
#+end_src

Use the direct command for projects outside =~/work= or nested below another
project directory. The launcher and the Emacs =C-c x a= command both delegate
terminal startup to =dev-session=.

Sessions are named =dev-<project>= and contain two tmux windows:

- =agent=: Codex, rooted at the project directory.
- =shell=: an independent shell for builds, tests, logs, and Git commands.

With the =C-x= tmux prefix, use =C-x a= for the agent and =C-x s= for the shell.

** Work in Emacs

Project commands use the =C-c p= prefix:

- =C-c p p=: switch project.
- =C-c p f=: find a project file.
- =C-c p b=: switch project buffer.
- =C-c p r=: search the project with ripgrep.
- =C-c p t=: run the conventional project test command.
- =C-c p k=: kill project buffers.

Code intelligence uses Eglot and Flymake:

- =C-c j r=: rename a symbol.
- =C-c j a=: apply a code action.
- =C-c j f=: format through Eglot.
- =C-c j e=: inspect diagnostics with Consult.

Use =F10= for buffers, =Shift+F10= for recent files, =C-.= for contextual
Embark actions, and =C-x g= for Magit.

** Work with Codex

Use =C-c x= to move explicit context from Emacs to the terminal agent:

- =C-c x a=: open the current project's Codex session in Ghostty.
- =C-c x f=: copy the current project-relative =file:line=.
- =C-c x r=: copy the active region with its file and line range.
- =C-c x t=: copy an editable task contract with current file or region context.

Paste into tmux with =C-x C-v=. Context is copied but never submitted
automatically, so the final prompt remains visible and editable.

A normal change loop is:

1. Check =git status= and create a checkpoint when the change is substantial.
2. Give Codex one concrete outcome, constraints, and acceptance checks.
3. Add precise file or region context from Emacs when it reduces ambiguity.
4. Inspect edits in Emacs or Magit instead of accepting the summary alone.
5. Run focused tests, then the broader project checks from the =shell= window.
6. Ask Codex to follow up on failures or use =/review= for a separate review pass.
7. Review the final diff and commit manually.

For substantial work, start from the =C-c x t= task contract. State one
concrete outcome, only the context that changes the answer, task-specific
constraints, and observable completion checks.

Choose model and permissions inside Codex with =/model= and =/permissions=.
Do not hard-code broad permissions into the project launcher.

** Measure agent utility

Use =workflow-log= for a two-week comparison of complete tasks, including
review and correction time:

#+begin_src sh
  workflow-log start ai debug "duplicate lesson investigation"
  workflow-log status
  workflow-log finish --review-fixes 1 --first-pass no --notes "one retry"

  workflow-log start manual refactor "extract validation helper"
  workflow-log finish --review-fixes 0 --first-pass yes
  workflow-log report
#+end_src

Modes are =ai= and =manual=. Categories are =debug=, =feature=, =refactor=,
=test=, =docs=, =review=, and =other=. Compare modes within the same category;
the report is descriptive because tasks are not randomly assigned. The TSV is
kept outside Git under =${XDG_STATE_HOME:-~/.local/state}/workflow-log/=
(where the shell expression means XDG state when set, otherwise
=~/.local/state=).

Use =workflow-log cancel= to discard an active timer. After the measurement
period, package only workflows that repeatedly save time or require the same
corrections; do not add skills or scheduled automation before that review.

** Project test detection

=C-c p t= selects the first matching command:

| Marker                 | Command          |
|------------------------+------------------|
| =mvnw=                 | =./mvnw test=    |
| =gradlew=              | =./gradlew test= |
| =pom.xml=              | =mvn test=       |
| =build.gradle[.kts]=   | =gradle test=    |
| =Cargo.toml=           | =cargo test=      |
| =build.zig=            | =zig build test= |
| =Makefile=             | =make test=       |

When no marker matches, Emacs uses the buffer's existing =compile-command=.

** Maintain this configuration

After editing the repo:

#+begin_src sh
  make check
  make sync
#+end_src

=make check= validates managed files and shell syntax. =make sync= installs the
repo-managed Emacs, tmux, niri, and helper configuration into the home directory.
